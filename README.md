# @c9up/quasar

Redis connections for the [Ream](https://github.com/C9up/ream) framework — named connections, pub/sub, health checks, clean shutdown.

A quasar is powered by a black hole feeding on the matter around it: this one feeds the app its data. Like every package in the cohort it is named for what it is, not for the technology it speaks — which is Redis.

This package owns **the connection, and nothing else**. The packages that store things in Redis — `@c9up/echo` (cache), `@c9up/bay` (queue), `@c9up/warden` (token blacklist) — keep taking a client through a structural contract, so they stay agnostic and this package stays optional.

## Install

```sh
pnpm add @c9up/quasar
```

`ream add @c9up/quasar` installs it, registers the provider and writes
`config/redis.ts`. The rest of this page assumes that has run.

## Configure

```ts
// config/redis.ts
import { defineConfig } from '@c9up/quasar'
import env from '#start/env'

export default defineConfig({
  connection: 'main',
  connections: {
    main: { url: env.get('REDIS_URL') },
    cache: { host: env.get('REDIS_HOST'), port: 6379, db: 1 },
    cluster: { clusters: [{ host: 'node-1', port: 7000 }, { host: 'node-2', port: 7001 }] },
  },
})
```

`defineConfig` refuses a default connection that is not declared, and an empty connection list — a typo there would otherwise surface as a connection to some default localhost. `redis.connection(name)` refuses an undeclared name the same way, including names only `Object.prototype` carries (`constructor`, `__proto__`).

A password may be a `Secret` — what `env.get()` returns for a variable declared `Env.schema.secret()` — and a port may be the string an env file holds. Both are converted on a copy as the client is built, so the config keeps the Secret. A port that is not a whole port number is refused rather than handed to ioredis, which would quietly dial 6379.

Printing the manager (`JSON.stringify`, `console.log`) shows where each connection points but no credential: passwords, usernames and URL userinfo come out as `[redacted]`. `redis.managerConfig` still reads the real config.

The config generated by `ream add` bounds the reconnect budget — ten attempts, then ioredis gives up and the next call opens a fresh connection — so a command issued during an outage fails in about three seconds instead of seventy-four. It also declares the env validations (`REDIS_PORT` a number, `REDIS_PASSWORD` a secret) when the host's ream can write them.

The config key and the container token stay `redis` — the **role**, the same way `@c9up/echo` binds `cache` and `@c9up/bay` binds `queue`.

Register the provider in `start/providers.ts` (or your app's provider list):

```ts
import QuasarProvider from '@c9up/quasar/provider'
```

It binds the manager as `'quasar.redis'` and `'redis'` in the container and seats it on the service accessor. `register` opens **no socket**: connections are built on first use.

## Use

```ts
import redis from '@c9up/quasar/services/main'

await redis.connection().set('user:42', payload, 'EX', 60)
await redis.connection('cache').get('user:42')
```

The Redis commands are callable straight on a connection **and on the manager**, where they run on the default connection:

```ts
await redis.set('user:42', payload, 'EX', 60)
```

The forwarded commands are an explicit list drawn from ioredis' command list, not every function on the client. Sharded pub/sub (`ssubscribe`) is not among them — it would put the command socket in subscriber mode — and neither is ioredis' EventEmitter. The raw client stays reachable as `connection.ioConnection` for anything not wrapped here. A connection also reports its state: `connectionName`, `status`, `subscriberStatus`, `lastError`, `isConnecting()` / `isReady()` / `isClosed()`.

LUA scripts go through `defineCommand` / `runCommand`; a script defined on the manager reaches every open connection and is remembered for the ones opened later.

## Pub/sub

```ts
await redis.subscribe('orders', (message, channel) => { /* … */ })
await redis.psubscribe('user:*', (channel, message, pattern) => { /* … */ })
await redis.publish('orders', JSON.stringify(order))
```

Redis puts a subscribed client into a mode where it accepts nothing but subscribe/unsubscribe, so a connection that both publishes and listens needs two sockets. The second one opens **lazily**, on the first subscribe, and never at all for a connection that only runs commands — meanwhile ordinary commands keep working on the first.

A pattern handler takes `(channel, message)` — the reverse of a channel handler's `(message, channel)`. It is deliberate: a pattern handler is called for channels it never named, so which one arrived is the first thing it needs. Both are strings, so getting them the wrong way round is silent.

Subscribing twice to one channel **stacks** the handlers — both are called. Pass the handler back to `unsubscribe` to drop just that one; the socket stays subscribed while others remain.

A failed subscription does **not** reject: a `subscribe` call is often left without `await`, and a rejection nobody handles would end the process. Failure arrives through `onError`, the `subscription:error` event, and the connection logger. `subscribed()` / `psubscribed()` are the awaitable forms, and they do reject.

A handler is registered before Redis acknowledges the subscription, so a message the server sends in the same packet as the acknowledgement is delivered. Closing a connection (`quit()`, `disconnect()`) drops its handlers; a later subscribe on it starts clean.

## Events

A connection emits these events, each with one payload object:

```ts
redis.connection().on('error', ({ error, connection }) => { /* … */ })
redis.connection().on('reconnecting', ({ connection, waitTime }) => { /* … */ })
redis.on('connection', (connection) => { /* each connection the manager opens */ })
```

`connect`, `wait`, `ready`, `close` and `end` carry `{ connection }`; clusters add `node:added`, `node:removed` and `node:error`. The pub/sub socket's lifecycle comes as `subscriber:connect`, `subscriber:ready`, `subscriber:error`, `subscriber:close`, `subscriber:reconnecting` and `subscriber:end` — that socket is internal and opened lazily, so nothing outside could listen to it otherwise. Subscriptions report `subscription:ready` / `subscription:error` and their `psubscription:` twins.

`on()` hands back a function that stops listening, `once(event)` a promise of the next payload, and `clearListeners()` drops what the application attached. Quasar's own listeners live on the ioredis client, out of reach of all three, so error recording and the manager's bookkeeping keep working whatever a teardown does.

## Tracing

Every command is published on the `quasar.redis.command` tracing channel, exported as `tracingChannels.redisCommand`. A subscriber receives the command's name and the connection's — never the arguments, which carry keys and values.

```ts
import { tracingChannels } from '@c9up/quasar'

tracingChannels.redisCommand.subscribe({
  start: ({ command, connection }) => { /* … */ },
  asyncEnd: ({ command }) => { /* … */ },
  error: ({ command, error }) => { /* … */ },
})
```

## Health

```ts
import { HealthChecks } from '@c9up/ream/health'
import { QuasarCheck, QuasarMemoryUsageCheck } from '@c9up/quasar'

export const healthChecks = new HealthChecks().register([
  new QuasarCheck(redis.connection()),
  new QuasarMemoryUsageCheck(redis.connection('cache'))
    .warnWhenExceeds('400 mb')
    .failWhenExceeds('800 mb')
    .cacheFor('1 minute'),
])
```

Each check is named after its connection — `Redis health check (main)`, `Redis memory consumption health check (cache)` — so two connections are two entries; `as(name)` renames one. Thresholds take bytes or a size (`'100 mb'`); an unreadable one throws `E_INVALID_BYTES_VALUE`. `compute(callback)` replaces how memory use is measured.

Both return `{ status, message, finishedAt, meta }` rather than throwing — a health endpoint reports, it does not crash. The meta says which connection and in what state (`connection: { name, status }`), and for memory `memoryInBytes: { used, warningThreshold, failureThreshold }`. Neither sends a command to a connection that is not ready: ioredis would queue it rather than fail it, and a readiness probe that hangs is the outage it exists to report. A connection still dialling gets three seconds; one that has already failed gets none.

A connection that was quit, or that the manager dropped once its socket ended, is reported as closed and never dialled again: the socket a check reopened would be tracked by nothing, outlive `quitAll()` and keep the process alive.

The memory thresholds default to 100 MB (warning) and 120 MB (failure), so a check left unconfigured can still fail.

## Shutdown

`quit()` and `disconnect()` act on **one** connection — the default one when no name is given — and `quitAll()` / `disconnectAll()` act on every open one.

`QuasarProvider.shutdown()` calls `quitAll()`. Without it a stopped process keeps its sockets and ioredis' reconnection timer keeps the event loop alive, so the server looks hung instead of exiting.

## Tests

The suite runs against a real server named by `REDIS_TEST_URL` — a mock would prove nothing about the part that actually bites. There is no default: pointing the suite at whatever Redis the machine runs would write to it. Start a throwaway one (`docker run --rm -p 6391:6379 redis:7-alpine`) and export its URL.
